# 舞台走位校验系统

一款舞台走位（Blocking）校验 Web 应用：在「舞台区域连接图」上标注各区域间的通行耗时、**通道容量**与**通道封闭时段**，为演员按时间下达「到位口令」（可带**停留时长**），系统从上一口令时刻出发**逐边推演**相邻口令之间的实际行进过程——进入连接若与封闭时段重叠，会在区域**原地等待**或**自动改走其他路径**，据此计算**最早到达时刻**并标出**无法按时抵达**的区段；两种走位模式算出逐边路线后，还会汇总所有演员对同一无向连接的**占用区间**做**通道占用冲突**校验，支持编辑后即时重算与一键导出 Markdown 校验报告。还可在当前校验模式下保存**走位方案基线快照**，编辑后即时对照基线列出新增 / 移除区段及状态、迟到、路线、通道冲突的变化。新增**应急疏散快照**：输入事件时刻并选择出口区域，按当前校验模式的实际路线还原每位演员当时的位置并计算最早疏散路线，页面按最晚撤离优先展示，报告追加同一快照。新增**跨演员口令依赖**：可在两条口令间维护「前置完成后至少等待 N 秒才可执行后置」的有向约束，保存前对整张依赖图做环检测（成环拒绝写入并提示闭环口令链），校验时按当前模式的实际时刻逐条判定满足 / 违约 / 无法判定，页面即时重算、删除口令级联清理，报告追加依赖汇总与明细。新增**排练数据 CSV 导入**：下载模板后批量导入排练口令，按「姓名 + 角色」复用演员、按区域名解析目标，上传即逐行预览时间 / 停留格式、未知或重名区域、文件内重复与现有口令冲突，错误行禁止提交；预览生成带数据版本的导入计划，提交时底库已变化返回 409 要求重新预览，否则一次性原子写入全部新演员和口令，成功后刷新校验结果并展示新增数量。

内置两种校验模式，可在结果区一键切换：

- **连续口令延误传导**（默认）：首条口令视为准时到位，之后逐段连续推演——实际出发时刻取「计划时刻与实际到达时刻的较晚值」再加停留时长，**某段迟到会传导给后续区段**，后续间隔充足时可**吸收延误、恢复准时**；
- **区段独立校验**：每段均从上一口令计划时刻出发，段与段互不影响（即旧版行为）。

技术栈：Node.js + Express + 原生 HTML/CSS/JavaScript（无任何前端构建步骤）。

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

启动后访问：**http://localhost:3000**（容器内服务端口 `3000`，Compose 默认映射到主机 `3000` 端口）

> 首次启动时，若数据文件不存在，系统会自动写入内置示例数据（9 个舞台区域、11 条连接——其中 2 条带封闭时段、1 条容量为 2、3 位演员、12 条口令、3 条跨演员口令依赖，含刻意设计的「等待」「绕行」「超时」「不可达」「停留导致迟到 → 延误传导 → 间隔吸收恢复准时」、两位演员并发占用「通道占用冲突」以及依赖在不同模式下「满足 / 违约 / 无法判定」的演示区段）。

## 配置项

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | Web 服务监听端口（Compose 中映射为主机 3000 端口） |
| `DATA_DIR` | `./data`（容器内 `/app/data`） | 数据文件 `data.json` 存放目录 |

Compose 默认将数据目录挂载为命名卷 `stage-data` 以持久化修改；执行 `docker compose down -v` 删除卷后重启即可恢复示例数据（也可在页面右上角点击「恢复示例数据」）。

## 本地开发（不用 Docker）

```bash
npm install
npm start
# 访问 http://localhost:3000
```

要求 Node.js ≥ 18。

## 功能说明

- **舞台区域**：维护区域名称与备注（如 舞台中央、侧台右、后台化妆间）。
- **区域连接**：维护无向连接、通行耗时（秒）、**通道容量**（同一时刻允许并发占用的人数，1～10，缺省 1）与**通道封闭时段**（可添加多段起止秒数区间），同一对区域仅允许一条连接。
- **演员**：维护演员姓名与角色。
- **排练数据 CSV 导入**：在「📥 排练数据 CSV 导入」卡片下载 CSV 模板、批量上传排练口令：
  - **演员复用 / 新建**：按「**姓名 + 角色**」匹配现有演员——唯一匹配则复用，无匹配则自动新建，同名且同角色不唯一时该行报错（不猜测是哪一位）；
  - **区域解析**：按区域名精确匹配，**未知区域 / 重名区域**均为错误行（导入不会新建区域）；
  - **逐行校验**：时间支持 `90`（秒）或 `01:30`（分:秒），停留秒数为 0～600 的整数（留空按 0）；同时标出**文件内重复行**（姓名 + 角色 + 区域 + 时间完全相同）与**现有口令冲突**（复用演员已有同时刻同区域口令）；
  - **模板与预览**：模板为带表头的 UTF-8 CSV（Excel 直接打开不乱码），上传后不写库、只展示逐行预览与新增演员 / 口令数量；**存在错误行时提交按钮禁用**；
  - **乐观并发**：预览计划带**数据版本**（底库区域 / 演员 / 口令的哈希）；提交时若底库已被修改（任何标签页的增删改），服务端返回 **409** 并要求重新预览，重新预览后再提交；
  - **原子写入**：提交时服务端按原始 CSV 重新解析校验，随后一次性写入全部新演员与口令并单次落盘，**任何失败均回滚、不会部分落库**；成功后自动刷新数据与校验结果并提示新增数量。
- **到位口令**：按「演员 + 目标区域 + 时间」下达口令，时间支持 `90`（秒）或 `01:30`（分:秒）两种输入格式；每条口令可设 **0～600 秒停留时长**（缺省 0，用于连续口令延误传导模式）。
- **校验结果**：对每位演员，将其口令按时间升序排列，逐边推演（时间依赖 Dijkstra）：
  - ✅ **按时**：最早到达时刻 ≤ 下一口令时刻，显示余量秒数、最早到达时刻与实际路线；
  - ❌ **超时**：最早到达时刻 > 下一口令时刻，红色高亮并显示「所需 X 秒 / 可用 Y 秒、缺口 Z 秒」；
  - ⛔ **不可达**：两区域在连接图上不连通（封闭时段只会造成等待或绕行，不会造成不可达）。
  - 🚶 **通道占用冲突**：结果区顶部汇总全部冲突事件，发生冲突的区段在路线旁逐条标记关联冲突。
- **延误传导展示**：连续口令延误传导模式下，结果区逐段列出**计划/实际出发时刻、实际到达、继承延误与最终迟到**，演员标题处给出传导链末端状态（最终迟到或「延误已全部吸收」）。
- **走位方案基线对比**：在当前校验模式下可将一次校验结果**保存为基线快照**；此后编辑区域、连接、演员或口令，结果区会**即时对比当前结果与基线**（无需手动刷新）：
  - 以「**演员 ID + 相邻口令 ID**」组成稳定区段键匹配，新增 / 删除 / 重排口令都不会按数组位置错配；结果区分组列出**新增区段**与**移除区段**；
  - **共有区段**逐项对比：按时 / 超时 / 不可达**状态**、**实际到达时刻**、**迟到秒数**、**实际路线**与**关联通道冲突**（冲突按「连接 + 超载时段」匹配，不依赖冲突序号）；
  - 顶部汇总徽章给出**状态转好 / 转差**、**迟到增减**、**通道冲突新增 / 解除**的区段计数；无差异时提示「与基线完全一致」；
  - 基线按校验模式分别保存：切换到另一种校验模式时，若该模式没有基线而另一模式存在，会**提示模式不一致且不做比较**（可一键清除另一模式的基线）；
  - 支持**覆盖**基线（用当前结果重新保存）与**清除**基线；基线随数据文件**持久化**（保存在数据文件的 `baselines` 字段中，恢复示例数据时一并清空）；
  - **导出的 Markdown 报告会追加同样的对比摘要**（基线信息、总体变化、汇总计数对比、新增 / 移除区段表与共有区段变化明细表）；当前模式没有基线时报告不包含该章节。
- **应急疏散快照**：在「应急疏散快照」卡片输入事件时刻并勾选一个或多个出口区域，系统按当前校验模式的实际路线还原每位演员当时的位置并计算最早疏散路线：
  - **位置还原**：逐边时间轴精确到秒——🚶 **通道行进中**（含所在通道、方向与剩余秒数）、⏱ **区域等待**（通道封闭等待 / 等待下一口令时刻）、🧍 **停留**（计划停留 / 走位结束后停留）；
  - **疏散计算**：位于通道者**先按原方向走完剩余路程**，再从到达区域按事件时刻之后的封闭时段（等待或绕行）计算到任一出口的最早路线；位于区域者从事件时刻直接计算；已位于出口区域者耗时为 0；
  - **位置未知**：因不可达链（区段不连通）或事件时刻早于走位时间轴而无法确定位置时，单独标为位置未知，**不做猜测**；
  - **结果展示**：按**最晚撤离优先**排序（无法疏散视为最晚），列出位置、出口、到达时刻、耗时与疏散路线；数据编辑或切换校验模式后快照随动重算；
  - **报告联动**：快照生成后，「导出校验报告」的 Markdown 会在文末追加同一快照。
- **跨演员口令依赖**：在「🔗 跨演员口令依赖」卡片选择前置 / 后置口令（可属于不同演员）并填写至少等待秒数，维护「前置口令完成后至少等待 N 秒，后置口令才可实际出发」的有向约束：
  - **成环拒绝**：每次新增保存前检查整张依赖图（含自环），**成环时返回 400 并在错误信息中给出闭环口令链（演员 + 时刻 + 区域），本次不写入**；同一对口令的同方向重复依赖返回 409；
  - **逐条判定**：校验时以**前置口令在当前模式下的实际到达时刻 + 其停留时长**作为完成时刻，与**后置口令的实际出发时刻**（前往该口令区段的实际出发时刻）比较，列出 ✅ **满足**（余量秒数）、❌ **违约**（缺口秒数）与 ❓ **无法判定**（前置 / 后任一端不可达、后置是其首条口令无实际出发等）；
  - **即时重算**：新增 / 删除依赖或编辑任何走位数据、切换校验模式后立即重新评估，结果区分违约 / 未知 / 满足排序展示；
  - **级联清理**：删除口令（含删除演员 / 区域连带删除口令）时自动删除与该口令相关的全部依赖；
  - **报告联动**：「导出校验报告」的 Markdown 追加「跨演员口令依赖」汇总徽章与明细表（前置完成、后置实际出发、相差秒数与结论）。
- **等待展示**：结果区在路线下方逐边列出出发 / 到达时刻，并以 ⏱ 徽标标出**等待位置（区域）与时长**。
- **即时重算**：任何新增 / 编辑 / 删除操作（含封闭时段、停留时长编辑）保存后立即重新校验并刷新结果。
- **导出报告**：点击「导出校验报告」下载 Markdown 格式报告，与当前校验模式一致（含汇总表、**通道占用冲突汇总与明细**、**跨演员口令依赖汇总与明细**、每位演员的区段明细、**逐边动态路线明细**，传导模式下另附**延误传导明细**）。
- **级联一致性**：删除区域会同时删除相关连接与口令；删除演员会同时删除其全部口令；删除口令（或因删除区域 / 演员连带删除口令）会同时删除相关的跨演员口令依赖。

## 排练数据 CSV 导入操作说明

1. 在「📥 排练数据 CSV 导入」卡片点击「**下载 CSV 模板**」，得到含 `姓名,角色,目标区域,时间,停留秒数,口令说明` 表头的 UTF-8 CSV（模板内附两行示例，正式导入前请删除或替换）。
2. 逐行填写排练口令：`姓名` + `角色` 用于匹配演员（角色可留空）；`目标区域` 必须与底库区域名**完全一致**；`时间` 填秒数（如 `90`）或 `mm:ss`（如 `01:30`）；`停留秒数` 留空按 0；`口令说明` 可留空。字段中如需逗号可用双引号包裹（`"` 用两个 `""` 表示）。
3. 点击「**选择 CSV 文件上传预览**」：页面逐行展示解析后的时间 / 停留、演员处理方式（复用 / 新建 / 重名）、区域匹配情况与全部错误（未知 / 重名区域、时间或停留格式错误、文件内重复、现有口令冲突、必填缺失等）。
4. **只要有错误行，「确认提交导入」按钮即为禁用状态**；按提示修改 CSV 后重新上传即可再次预览。
5. 全部行可导入后点击「**确认提交导入**」：若预览后底库被其他操作修改，会收到 409 提示「底库数据已变化，请重新预览」，点击提示中的「**重新预览**」按钮即可基于最新底库再次校验；
6. 提交成功后页面提示「**新增 N 位演员、M 条到位口令**」，演员 / 口令表格与校验结果自动刷新。整个提交为原子操作：写入过程中任何失败都会回滚，不会出现部分落库。

## 走位方案基线对比操作说明

1. 在结果区顶部用模式切换按钮选择校验模式（默认「连续口令延误传导」）。
2. 点击「**保存当前结果为基线**」，系统会对该模式保存一份基线快照（记录保存时间）。
3. 之后在下方任意面板新增 / 编辑 / 删除区域、连接、演员或口令，结果区顶部立即出现对比摘要：
   - 徽章：新增 / 移除区段数、状态转好 / 转差、迟到减少 / 增加、冲突新增 / 解除；
   - 明细：🟢 新增区段、🔴 移除区段、🟡 共有区段变化（状态、实际到达、迟到、路线、关联冲突的基线 → 当前对照）。
4. 想以当前方案为新基准时点「**覆盖基线**」；不再需要时点「**清除基线**」。
5. 切到另一种校验模式时：基线是**按模式分别保存**的。若另一模式存在基线而当前模式没有，顶部会黄色提示「模式不一致，不比较」——可按提示清除另一模式基线，或切回原模式继续查看；在当前模式另存基线即可单独比较。
6. 基线随数据持久化（Docker 命名卷 / `DATA_DIR` 内的数据文件），重启不丢失；「恢复示例数据」会同时清空基线。
7. 点击「📄 导出校验报告」下载的 Markdown 在汇总表之后追加「走位方案基线对比摘要」，内容与页面一致。

## 跨演员口令依赖操作说明

1. 在「🔗 跨演员口令依赖」卡片：左侧下拉选择**前置口令**（按演员分组、组内按时间排序），右侧下拉选择**后置口令**，填写**至少等待秒数**（0～3600 的整数），点击「添加依赖」。
2. 保存成功后下方表格即时列出评估结果：前置口令（演员 / 时刻 / 区域 / 停留）、至少等待秒数、后置口令、前置完成时刻 / 后置实际出发 / 允许最早出发、结论与相差秒数（✅ 满足显示余量、❌ 违约显示缺口、❓ 无法判定显示原因）。
3. 若新增约束会导致依赖图成环，页面会弹出服务端返回的错误（含完整闭环口令链），本次依赖不会写入；先删除环上的某条已有依赖再重试即可。
4. 编辑区域 / 连接 / 演员 / 口令、添加或删除依赖、切换校验模式后，评估结果都会**即时重算**（同一依赖在区段独立与延误传导模式下结论可能不同）。
5. 删除口令会自动级联清理相关依赖（删除演员 / 区域连带删除口令时同理），无需手工处理；点击每行「删除」可单独移除一条依赖。
6. 点击「📄 导出校验报告」下载的 Markdown 会在通道冲突章节之后追加「跨演员口令依赖」汇总与明细表。

## 应急疏散快照操作说明

1. 启动服务后访问 **http://localhost:3000**（Docker Compose 默认将容器内 `3000` 端口映射到主机 `3000` 端口；本地 `npm start` 同样为 3000 端口，可用 `PORT` 环境变量修改）。
2. 在「校验结果」卡片顶部选择校验模式（快照按**当前模式**的实际路线还原位置）。
3. 在「🚨 应急疏散快照」卡片输入**事件时刻**（支持 `90` 秒或 `01:30` 分:秒两种格式），并勾选**一个或多个出口区域**，点击「**生成疏散快照**」。
4. 结果区按**最晚撤离优先**列出每位演员：事件时刻位置（区域等待 / 停留 / 通道行进中及剩余路程）、出口、到达时刻、耗时与疏散路线；**无法疏散**（位置已知但无任何出口可达）排最前，**位置未知**（不可达链或时间轴未开始，不猜测）单独列于文末。
5. 快照生成后：编辑区域 / 连接 / 演员 / 口令或切换校验模式，快照会按最新数据与当前模式**即时重算**；点击「清除快照」可收起结果并恢复报告为不含快照的版本。
6. 快照生成期间点击「📄 导出校验报告」，下载的 Markdown 会在文末追加**同一快照**（事件时刻、出口、最晚撤离时刻、快照表与位置未知名单）。

## 通道封闭时段规则

- 每条连接可维护 **0 至多段**封闭时段，每段为起止秒数区间 `[开始, 结束)`（**含开始、不含结束**），开始必须严格小于结束，均为不小于 0 的整数秒。
- 演员在时刻 `t` 进入一条通行耗时为 `w` 的连接时，占用区间为 `[t, t+w]`；若该区间与任一段封闭区间**重叠**（`t < 结束` 且 `t+w > 开始`），则此时刻不可进入。
- 冲突时演员在该连接**起点所在的区域内等待**，直至封闭结束（最早可进入时刻 = 封闭结束时刻；多段封闭会依次向后滚动计算）。
- 校验算法会比较「等待」与「绕行其他路径」两种方案，取**最早到达时刻**的路线作为实际路线；等待位置与时长会在结果区和报告中展示。
- 封闭时段为有限区间，因此只会推迟到达、不会影响图连通性；「不可达」仍仅表示区域间没有任何连接路径。
- 旧数据文件中没有封闭时段字段的连接按「无封闭」处理，完全兼容。

## 通道占用冲突规则

- 在两种走位模式（区段独立 / 连续口令延误传导）各自算出逐边路线**之后**，将所有演员对每条**无向连接**的占用按半开区间 **`[进入, 离开)`** 汇总：进入时刻 = 该边实际出发时刻，离开时刻 = 实际到达时刻。
- 每条连接有**容量**（同一时刻允许并发占用的人数），默认为 **1**，可在连接编辑中设为 **1～10** 的整数；旧数据文件中没有容量字段的连接按 1 处理。
- 任一时刻并发占用人数（按演员去重）**超过容量**即生成冲突事件；超载状态先消失再出现的区间会被切开，**首尾恰好相接的连续超载区间合并为一条**。冲突事件列出：所在通道、容量、起止时刻与持续秒数、**峰值人数**，以及每位参与演员的**方向、进入/离开时刻、关联区段**。
- **首尾恰好相接不算重叠**：一方离开时刻恰等于另一方进入时刻时，不构成并发（半开区间）。
- **等待时间不占用通道**：因封闭时段在前一区域等待的时段不计入任何连接的占用。
- 结果区顶部给出跨演员的冲突汇总与明细卡片；涉及冲突的区段在其路线旁标记关联冲突（通道、时刻、峰值/容量）。
- Markdown 报告在汇总表中新增「🚶 通道占用冲突」计数，并增加「通道占用冲突汇总」一节（汇总表 + 每条冲突的演员 / 方向 / 起止 / 关联区段明细）；各区段表与路线明细中标注关联冲突。
- 注意：冲突是对**已推演路线**的事后校验，不会改变演员的出发 / 到达时刻；两种模式算出的路线不同，冲突结果也随之不同。

## 连续口令延误传导规则

- 每条口令可维护 **0～600 秒**的停留时长（整数秒，缺省 0；旧数据文件中没有该字段的口令按 0 处理，完全兼容）。
- 对每位演员按口令时间升序**连续推演**：**首条口令视为准时到位**（实际到达 = 计划时刻）。
- 从某条口令前往下一条时，**实际出发时刻 = max（该条计划时刻，实际到达该条的时刻） + 该条停留时长**；随后复用封闭等待 / 绕行算法计算下一条口令的实际到达。
- 某段迟到会**传导**给后续区段（继承延误逐段累积）；若后续口令间隔充足，到达仍不晚于计划时刻，则**延误被吸收**、恢复准时，不再向后传导。
- 结果区逐段展示：计划出发（计划时刻 + 停留）、实际出发、实际到达、继承延误（到达本段起点时已晚的秒数）与最终迟到（到达终点口令时晚于计划的秒数）。
- 不可达区段无法计算实际到达，其后区段自下一口令的**计划时刻**重新起算（传导链中断处会在报告明细中注明）。
- 「区段独立校验」模式不使用停留时长，也不做延误传导，行为与旧版一致。

## 应急疏散快照规则

- **位置还原**：以当前校验模式（区段独立 / 连续口令延误传导）已推演的逐边实际路线为唯一依据，将每位演员的走位展开为覆盖「首条口令时刻 → 之后」的时间轴，定位事件时刻所在区间：
  - 🚶 **通道行进中**：事件时刻落在某条连接的占用区间 `[进入, 离开)` 内；
  - ⏱ **区域等待**：在区域内等待封闭时段结束，或早到后等待下一口令计划时刻；
  - 🧍 **停留**：口令的计划停留时长内，或全部口令完成后停留在最终区域。
- **位于通道者**：先按原方向走完剩余路程（抵达时刻 = 该边实际到达时刻），再从到达区域计算疏散路线；区段独立模式下若后段口令按计划时刻重新起算导致位置窗口被截断，剩余路程仍以该边**真实抵达时刻**为准。
- **位于区域者**：从所在区域、事件时刻直接计算疏散路线；已位于出口区域者到达时刻即事件时刻、耗时 0。
- **疏散路线**：复用时间依赖 Dijkstra，在全部所选出口中取**到达时刻最早**者；事件时刻之后的封闭时段仍会造成等待或绕行（与走位校验同一套规则）。
- **位置未知**：事件时刻处于不可达区段（连接图不连通）期间、早于首条口令时刻、或演员没有口令时，单独标为位置未知，**不猜测**其位置；连续口令延误传导模式下，不可达区段自下一口令计划时刻起按该模式的重算规则恢复可知。
- **无法疏散**：位置已知但没有任何出口可达（如处于无连接的孤立区域），视为最晚撤离，排在结果最前。
- **排序**：结果按最晚撤离优先（无法疏散 → 到达时刻降序），位置未知者不参与排序、单独列出。
- 快照不修改任何走位数据，也不参与通道占用冲突与基线对比的计算；报告中的快照与页面为同一次计算结果。

## 跨演员口令依赖规则

- 依赖是两条口令之间的**有向约束**：`前置口令 --至少等待 N 秒--> 后置口令`，两条口令**可属于不同演员**（也可以约束同一演员的两条口令）；等待秒数为 **0～3600 的整数**。
- **完成时刻**（前置）：前置口令在**当前校验模式**下的**实际到达时刻 + 该口令的停留时长**（两种模式均使用口令自身的停留时长字段；停留期间演员仍在该口令区域）。
- **实际出发时刻**（后置）：前往后置口令的那个区段（同一演员按时间排序的上一条口令 → 后置口令）在当前模式下推演得到的**实际出发时刻**，其中已包含封闭时段等待、绕行与延误传导的影响。
- 判定：后置实际出发 ≥ 前置完成 + 等待 N 秒即 **✅ 满足**，相差秒数为余量；否则 **❌ 违约**，相差秒数为负的缺口（报告与页面显示「缺 X 秒」）。
- **❓ 无法判定**：前置 / 后置口令缺失或未参与推演、前往任一端口令的区段**不可达**（实际到达未知）、或后置口令是该演员的**首条口令**（没有前往该口令的区段，无实际出发时刻）时，不猜测时刻、单独标为无法判定并注明原因。
- 依赖**不改变走位推演**（不会推迟任何出发 / 到达时刻），仅在两种模式各自算出实际路线之后做事后校验，与通道占用冲突同级；模式切换后同一张依赖图会按新模式的时刻事实重新判定。
- **环检测**：新增依赖保存前对整张依赖图做 DFS 环检测，成环（含自环）时整次请求 400 失败、**不写入任何数据**，错误信息包含可直接阅读的闭环口令链（如 `李四 00:20 舞台中央 → 张三 00:35 二层平台 → 李四 00:20 舞台中央`）；需删除环上某条已有依赖后才能添加新约束。
- **级联清理**：删除口令时自动删除引用该口令（任一端）的依赖；删除演员 / 区域连带删除口令时同样级联清理。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/data` | 获取全部数据（区域 / 连接 / 演员 / 口令 / 口令依赖） |
| GET | `/api/validate?mode=…` | 执行走位校验；`mode` 为 `classic`（区段独立，缺省）或 `propagate`（连续口令延误传导），返回区段级结果（含最早到达时刻、逐边路线与等待明细；传导模式另含计划/实际出发、继承延误、最终迟到）；顶层 `conflicts` 为通道占用冲突事件列表，`summary.conflicts` 为冲突计数，相关区段上带 `conflicts` 关联标记；顶层 `dependencies` 为跨演员口令依赖评估结果（`items` 明细含前置完成 / 后置实际出发 / 相差秒数与 `satisfied`/`violated`/`unknown` 状态，`summary` 为三类计数，`summary.dependencies*` 同步给出计数）。结果另含：`baseline`（当前模式基线元信息）、`baselines`（两种模式的基线元信息）、`comparison`（当前模式存在基线时的对比摘要，否则为 `null`） |
| GET | `/api/evacuation?mode=…&time=…&exits=…` | 应急疏散快照：`time` 为事件时刻（不小于 0 的整数秒），`exits` 为逗号分隔的出口区域 ID（至少一个）；按 `mode` 的实际路线还原每位演员位置并计算到任一出口的最早疏散路线。返回 `entries`（按最晚撤离优先排序，含位置、出口、到达时刻、耗时与逐边路线；无法疏散者 `status` 为 `unreachable`）、`unknown`（位置未知名单及原因）与 `summary`（含最晚撤离到达时刻 `latestArrival`） |
| GET | `/api/report?mode=…` | 下载 Markdown 校验报告（`mode` 含义同上，含通道占用冲突汇总与明细、**跨演员口令依赖汇总与明细**；传导模式报告另含延误传导明细）；当前模式已保存基线时追加「走位方案基线对比摘要」；可选附加 `time` 与 `exits` 参数（含义同上），同时在报告末尾追加同一份「应急疏散快照」 |
| POST | `/api/dependencies` | 新增跨演员口令依赖，请求体 `{ predecessorId, successorId, waitSeconds }`；保存前对整张依赖图做环检测，**成环（含自环）返回 400 且不写入**，错误体 `error` 含闭环口令链、`cycle` 为口令 ID 链；同方向重复依赖返回 409；`waitSeconds` 需为 0～3600 的整数 |
| DELETE | `/api/dependencies/:id` | 删除一条口令依赖；删除口令 / 演员 / 区域时相关依赖由服务端自动级联清理，无需调用本接口 |
| POST | `/api/baseline/:mode` | 保存（或覆盖）指定模式（`classic` / `propagate`）的基线快照，基线随数据持久化 |
| DELETE | `/api/baseline/:mode` | 清除指定模式基线；`:mode` 传 `all` 清除全部模式基线 |
| POST | `/api/reset` | 恢复内置示例数据（同时清空全部基线） |
| GET | `/api/import/template` | 下载排练数据导入 CSV 模板（UTF-8 带 BOM、含表头与示例行） |
| POST | `/api/import/preview` | 上传 CSV 生成导入预览（不写库）：请求体 `{ csv }`，返回 `rows`（逐行解析结果与 `issues` 错误列表、`valid` 标记、演员复用 / 新建状态与区域匹配状态）、`newActors`（将新建的演员）、`summary`（总行数 / 可导入 / 错误行 / 新增演员 / 新增口令 / 未知区域 / 重名区域 / 文件内重复 / 冲突计数）与 `version`（底库数据版本哈希）；CSV 结构错误（空文件、缺必需列、引号未闭合、仅有表头）返回 400 |
| POST | `/api/import/commit` | 提交导入：请求体 `{ csv, version }`；底库版本与 `version` 不一致返回 **409**（要求重新预览）；重新解析后仍有错误行返回 400；校验通过则一次性原子写入全部新演员与口令，返回 `{ createdActors, createdCues, version }`（201），任何写入失败均回滚、不部分落库 |
| POST / PUT / DELETE | `/api/areas`、`/api/edges`、`/api/actors`、`/api/cues`（`/:id`） | 四类资源的增改删 |

`edges` 的创建 / 更新请求体示例：

```json
{
  "a": "area-wing-r",
  "b": "area-center",
  "seconds": 4,
  "capacity": 1,
  "closures": [ { "start": 10, "end": 14 }, { "start": 30, "end": 36 } ]
}
```

`closures` 可省略（等价于无封闭）；每段需满足 `0 ≤ start < end` 且为整数秒，否则返回 400。

`capacity`（通道容量）可省略：创建时缺省为 `1`，更新时不传则保留原值；需为 `1～10` 的整数秒，否则返回 400。旧数据文件中没有该字段的连接按容量 1 处理，完全兼容。

`cues` 的创建 / 更新请求体示例：

```json
{
  "actorId": "actor-zhang",
  "areaId": "area-center",
  "time": 20,
  "dwell": 8,
  "note": "上台亮相"
}
```

`dwell`（停留时长）可省略，缺省为 `0`；需为 `0～600` 的整数秒，否则返回 400。更新时不传 `dwell` 则保留原值。

`dependencies` 的创建请求体示例：

```json
{
  "predecessorId": "cue-l2",
  "successorId": "cue-z3",
  "waitSeconds": 5
}
```

含义：`cue-l2`（前置口令）在当前模式下实际到达并完成停留后，至少再等 5 秒，`cue-z3`（后置口令）的实际出发时刻才允许到来；两条口令可属于不同演员。新增后服务端立即对整张依赖图做环检测，成环返回 400（含闭环口令链）且不写入；同方向重复返回 409。

`/api/import/preview` 与 `/api/import/commit` 的请求体示例：

```json
{
  "csv": "姓名,角色,目标区域,时间,停留秒数,口令说明\n张三,饰 王子,舞台中央,01:30,8,上台\n赵六,饰 侍卫,侧台右,45,,候场",
  "version": "a852dd9e962fb02552ff03688ea40034faa2133382639a7dde4cb5e45551fa4"
}
```

`csv` 为 CSV 文件原文（`version` 仅提交时需要，取自预览响应）。行级错误码（`rows[].issues[].code`）：`name-required` / `name-length` / `role-length`（姓名角色缺失或超长）、`area-unknown`（未知区域）、`area-ambiguous`（重名区域）、`actor-ambiguous`（同名同角色演员不唯一）、`time-required` / `time-format`（时间缺失或格式错误）、`dwell-format`（停留秒数非 0～600 整数）、`note-length`（说明超长）、`duplicate`（文件内重复）、`conflict`（与现有口令冲突）。

## 项目结构

```
├── server.js            # Express 入口
├── src/
│   ├── store.js         # JSON 文件持久化 + 示例数据初始化（含基线存储）
│   ├── graph.js         # 时间依赖推演：封闭时段等待 / 绕行 + 最早到达（Dijkstra）
│   ├── conflicts.js     # 通道占用冲突：按无向连接汇总 [进入,离开) 占用、容量校验、连续超载合并
│   ├── validate.js      # 走位校验核心逻辑（simulateActor 逐段推演为校验与疏散快照共用事实来源）
│   ├── evacuation.js    # 应急疏散快照：还原事件时刻位置（等待 / 停留 / 通道）、剩余路程接驳、最早疏散路线
│   ├── dependencies.js  # 跨演员口令依赖：依赖图环检测（返回闭环口令链）、口令标签与成环错误文案
│   ├── import.js        # 排练数据 CSV 导入：CSV 解析、逐行预览（格式 / 未知重名区域 / 重复 / 冲突）、数据版本、原子提交
│   ├── baseline.js      # 基线对比：演员 ID + 相邻口令 ID 稳定键匹配，状态 / 到达 / 迟到 / 路线 / 冲突差异
│   ├── report.js        # Markdown 报告生成（含基线对比摘要、冲突汇总明细、口令依赖汇总明细、动态路线明细与疏散快照）
```
